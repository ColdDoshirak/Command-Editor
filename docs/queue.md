# Система очереди (Queue)

Команды, у которых включена очередь, исполняются **последовательно внутри своей группы**: следующий звук стартует только после того, как закончится предыдущий. Это нужно для музыки и других длинных звуков, которые иначе перебивали бы друг друга.

Группы без очереди работают как раньше — звук играет сразу, новый может перебить старый (зависит от настройки *Allow sounds to interrupt*).

## Как это устроено

- На каждую группу с включённой очередью создаётся своя очередь (`asyncio.Queue`) и свой воркер, который достаёт команды по одной и ждёт завершения звука.
- Разные группы играют **параллельно** — у каждой свой аудио-канал.
- Ограничение размера очереди — через семафор: при переполнении команда отклоняется, а списанные очки возвращаются.

## Настройка группы

Вкладка **Group Settings**:

1. **Queue Enabled** — включить очередь для группы.
2. **Audio Channel** — канал воспроизведения:
   - `0` — общий канал (звуки группы могут перебивать друг друга, как без очереди);
   - `1–32` — выделенный канал (параллельное воспроизведение, не перебивает общий).
   - Для музыки рекомендуется отдельный канал (например, `1`) и отдельная группа `SONG`.
3. **Max Queue Size** — лимит ожидания (0 = без лимита).
4. **Persist Queue** — сохранять очередь между перезапусками (см. ниже).

Нажмите **Save Settings** — изменения применятся к работающему боту без перезапуска.

## Команды

| Команда | Кто | Что делает |
|---|---|---|
| `!queue` | все | сводка по всем активным очередям (`Группа: N`) |
| `!queue GROUP` | все | список ожидающих в группе: позиция, пользователь, команда |
| `!skip` | модер | остановить текущий звук на общем канале (0) |
| `!skip GROUP` | модер | остановить текущий звук группы (на её канале) |
| `!clear GROUP` | модер | полностью очистить очередь группы |
| `!volume <0-100>` | модер | громкость группы по умолчанию (настраивается в Sys.Commands, по умолчанию `SONG`) |
| `!volume GROUP <0-100>` | модер | громкость конкретной группы; применяется к текущему треку сразу и сохраняется на будущее |

> Имена групп в командах не чувствительны к регистру.

## Порядок и стоимость

- Команда встаёт в очередь **после** проверки кулдаунов и списания очков.
- Если очередь переполнена — команда не принимается, очки возвращаются, приходит сообщение.
- Воркер исполняет команду: стоимость (если ещё не списана), звук (до завершения), затем текстовый ответ.

## Сохранение очереди (Persist Queue)

По умолчанию очередь **не** сохраняется — при перезапуске программы ожидающие команды теряются. Это осознанное поведение: не каждый хочет, чтобы музыка «доигрывала» после рестарта.

Если нужно сохранить очередь группы:

1. В **Group Settings** включите **Persist Queue** для этой группы.
2. После каждого обработанного элемента остаток очереди пишется в `config.json` (раздел `queue_persistence`).
3. При следующем запуске бота очередь группы восстанавливается и продолжает отыгрываться.

Нюансы:

- Восстановленные команды исполняются по сохранённым данным (звук + ответ). Живого Twitch-сообщения у них нет, поэтому чат-ответы при восстановлении не уходят в чат — только звук и лог.
- `!clear GROUP` сбрасывает и сохранённую очередь, чтобы после рестарта не «воскресали» очищенные элементы.
- Хранится только для групп с включённым **Persist Queue**; остальные группы не трогаются.

## Пример: музыка

1. Создайте группу `SONG`, назначьте канал `1`, включите очередь и (опционально) Persist Queue.
2. Перенесите в группу `SONG` все музыкальные команды.
3. Зрители ставят музыку в очередь: `!song ...` — треки играют по одному, не перебивая.
4. Модер управляет: `!queue SONG` (что играет/ждёт), `!skip SONG` (пропустить), `!volume SONG 50` (громкость), `!clear SONG` (очистить).
