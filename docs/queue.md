# Система очереди (Queue)

Команды, у которых включена очередь, исполняются **последовательно внутри своей группы**: следующий звук стартует только после того, как закончится предыдущий. Это нужно для музыки и других длинных звуков, которые иначе перебивали бы друг друга.

Группы без очереди работают как раньше — звук играет сразу, новый может перебить старый (зависит от настройки *Allow sounds to interrupt*).

## Как это устроено

- На каждую группу с включённой очередью создаётся своя очередь и свой воркер: он берёт команды по одной и ждёт окончания звука.
- Разные группы играют **параллельно**, у каждой свой аудиоканал.
- Лимит очереди считается по факту: ожидающие плюс текущая команда. При переполнении команда отклоняется, а списанные очки возвращаются.
- Сохранение настроек группы применяется к работающему боту сразу и **не обрывает** играющий трек.
- Если очередь у группы выключить, уже оплаченные команды доиграют, а новые будут исполняться сразу.

## Настройка группы

Вкладка **Group Settings** (подсказки есть на заголовках колонок):

1. **Queue**: включить очередь для группы.
2. **Channel**: канал воспроизведения.
   - `shared` (0): общий канал, звуки могут перебивать друг друга.
   - `1–32`: свой канал, играет параллельно и не перебивает общий. Двум группам с очередью не стоит давать один и тот же канал, программа об этом предупредит.
3. **Max size**: сколько команд может стоять в очереди, включая текущую (`unlimited` = без лимита).
4. **Persist**: сохранять очередь между перезапусками (см. ниже).
5. **Announce**: писать зрителю его место в очереди (только если перед ним уже кто-то есть).

Нажмите **Save Settings**.

## Вкладка Queue Control

- Блок **Now playing**: что играет сейчас, кто заказал, сколько прошло.
- **Pause / Resume**: текущая команда доигрывает, новые не стартуют, порядок не меняется.
- **Skip**: пропустить то, что играет сейчас (звук и текстовый ответ).
- Список **Up next**: перетаскивание, кнопки **Up/Down**, **Remove** (или клавиша Del), **Clear all** (с подтверждением). Удаляется ровно выбранная запись, даже если в очереди несколько одинаковых команд; текущий трек при этом не прерывается.
- В теме **Midnight** внизу окна постоянно видна полоса Now playing с кнопками Pause/Skip для каждой очереди.

## Команды

| Команда | Кто | Что делает |
|---|---|---|
| `!queue` | все | сводка по всем активным очередям (`Группа: N`) |
| `!queue GROUP` | все | что играет сейчас и следующие (до 15) одной строкой |
| `!skip` | модер | пропустить текущее в единственной играющей очереди; иначе остановить общий канал |
| `!skip GROUP` | модер | пропустить то, что сейчас играет в группе |
| `!skip COMMAND` | модер | убрать последнюю ожидающую запись этой команды (текущий трек не трогается) |
| `!clear GROUP` | модер | очистить ожидающие команды группы |
| `!volume <0-100>` | модер | громкость группы по умолчанию (настраивается в Sys.Commands, по умолчанию `SONG`) |
| `!volume GROUP <0-100>` | модер | громкость группы; применяется к текущему треку сразу и сохраняется. `0` = без звука |

> Имена групп в командах не чувствительны к регистру.

## Порядок и стоимость

- Команда встаёт в очередь **после** проверки кулдаунов и списания очков. Кулдаун начинается, только когда команда принята в очередь.
- Если очередь переполнена — команда не принимается, очки возвращаются, приходит сообщение.
- Воркер исполняет команду: стоимость (если ещё не списана), звук (до завершения), затем текстовый ответ.

## Сохранение очереди (Persist Queue)

По умолчанию очередь **не** сохраняется — при перезапуске программы ожидающие команды теряются. Это осознанное поведение: не каждый хочет, чтобы музыка «доигрывала» после рестарта.

Если нужно сохранить очередь группы:

1. В **Group Settings** включите **Persist Queue** для этой группы.
2. При каждом изменении очереди она пишется в `config.json` (раздел `queue_persistence`), включая трек, который играет сейчас: после сбоя он не потеряется.
3. При следующем запуске бота очередь группы восстанавливается и продолжает отыгрываться.

Нюансы:

- Восстановленные команды исполняются по сохранённым данным (звук + ответ). Живого Twitch-сообщения у них нет, поэтому чат-ответы при восстановлении не уходят в чат — только звук и лог.
- `!clear GROUP` сбрасывает и сохранённую очередь, чтобы после рестарта не «воскресали» очищенные элементы.
- Хранится только для групп с включённым **Persist Queue**; остальные группы не трогаются.

## Пример: музыка

1. Создайте группу `SONG`, назначьте канал `1`, включите очередь и (опционально) Persist Queue.
2. Перенесите в группу `SONG` все музыкальные команды.
3. Зрители ставят музыку в очередь: `!song ...` — треки играют по одному, не перебивая.
4. Модер управляет: `!queue SONG` (что играет/ждёт), `!skip SONG` (пропустить), `!volume SONG 50` (громкость), `!clear SONG` (очистить).
